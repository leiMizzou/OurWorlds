# M2.5 设计：坐标瞬移 + 分享/展示建造（强交互）

目标里的"发坐标→别人瞬移过去参观""创建并分享建造"。两块都尽量复用已有机制，核心逻辑可无头单测。

## A. 瞬移到某玩家（visit）
- **数据已就位**：客户端每帧通过 `_rpc_sync_players` 收到所有人的位置，存在 `NetworkManager._avatars[eid]`（RemoteAvatar，带 `global_position`）。所以"去找某人"无需新服务器 RPC——读对方 avatar 当前位置即可。
- **入口**：在线列表（`ChatPanel` 左栏每个 human/agent 旁）加一个「前往」按钮 → `Main.teleport_to_peer(eid)`。
- **实现**：`NetworkManager.peer_position(eid) -> Vector3`（从 `_avatars` 或 server 端 `_peers` 取）；`Main.teleport_to_peer(eid)`：取位置 → `world.prime(chunk_of(pos))`（同步生成目标区块，落地可踩）→ `player.global_position = pos + 安全抬升` → `player.velocity = ZERO`。复用 AgentBridge.goto 的"prime 后落点"套路。
- **可测**：`NetworkManager.peer_position(eid)` 纯查询，单测（注入 _avatars/_peers 断言返回）。瞬移落点的"目标区块已就绪"用现有 World 测法。视觉确认归人工。

## B. 分享 / 展示建造（blueprint）
- **捕获**：选一个长方体区域（min..max）→ 读 `WorldData.get_block` 生成蓝图：`{size:[dx,dy,dz], blocks:{"lx,ly,lz": id}}`（只存非空气，省体积；锚点相对化）。
- **序列化**：蓝图存成 JSON（`user://blueprints/<名字>.json`），可发给别人/进仓库。
- **粘贴/展示**：在目标锚点把蓝图写回 → 联机时走正常编辑链路（`request_block_edits` → 服务器校验/广播），所以别人也看得见你"展示"出来的建造。
- **可测（无头）**：`Blueprint.capture(world_data, min, max) -> Dictionary`、`Blueprint.serialize/deserialize`、`Blueprint.paste_edits(blueprint, anchor) -> Array[edit]`（返回编辑列表，喂给 request_block_edits）。捕获→序列化→反序列化→粘贴 round-trip 断言方块一致。新文件 `scripts/Blueprint.gd`（纯 RefCounted，像 WorldData 一样可无头测）+ `tests/test_blueprint.gd`。
- **入场分享**：M4 起可把蓝图存 Nakama；M2.5 先做本地文件 + 联机内粘贴。

## 范围（M2.5）
做：peer_position + teleport_to_peer + 在线列表「前往」按钮；Blueprint 捕获/序列化/粘贴 + 单测 + 一个"复制选区→另处粘贴"的最小入口。
暂不做：蓝图云端库（M4）、跨服分享、版权/审核（M6）。
